# v15 PDCA 계획 · ORS 즉시 갱신과 심층 진행현황

## P — 확인된 현황

- 공개 v14는 생성 시점 자료를 HTML에 내장해 새 ZIP이 들어와도 자동 갱신되지 않는다.
- 관리 Tool 2026 신청일 행 53개, 최신 산업 ORS 2026 접수 근거 행 27개, 2026 처리 이력/직접 날짜 행 169개다. 동일 사업명·일자의 1:1 대조 후보는 23쌍이나 확정 키가 없어 자동 합산·병합하지 않는다.
- ORS 원본은 7·9월 모두 같은 계열의 XLS 양식이다. 신규 ZIP은 기존 `monthly_ors.py`의 구조·해시 검증과 불변 원본 보관을 사용한다.

## D — 변경 범위

1. 통계: 관리 Tool 원장을 주원천으로 연도·월·상태·기관·방법론·분야 추이를 표시한다. ORS는 별도 비교/최신성 지표로만 둔다.
2. 진행: 월별 접수, 출처별 단계 분포, 보완·의견·안내·위험 대기열, 2026년 모든 관련 원본행을 검색·필터한다.
3. 상세: 건별 별도 주소에서 신청 내용과 원본 전체 필드, 기관·담당자 표기와 처리 이벤트 타임라인, 근거/확인 필요사항을 표시한다.
4. 갱신: 새 ZIP 수신 → 구조 검사·중복 제거·DB 스냅샷 → 정적 자산 재생성·공개 배포. 열린 화면은 판본 파일을 확인해 새 자료가 게시되면 갱신한다.

## C — 필수 검증

- 관리 Tool/ORS 수치와 원본행 대조, 2026 접수·활동 기준의 중복/누락 검사.
- 7월·9월 기준과 추가 월별 ZIP 시험 모두에서 생성·페이지·Excel 링크 검증.
- 상세 페이지의 원본 파일·시트·행·기관·날짜 추적, 안내 제안과 원본 기록 구분.
- 공개 배포 후 익명 접근, 필터·검색·상세 이동·자동 새 판본 감지 확인.

## A — 제한과 판단

- `즉시`는 지정된 ZIP 업로드 이후 자동 처리·배포가 끝나는 대로 열린 화면이 새 판본을 감지한다는 뜻이다. GitHub Pages만으로 로컬 Dropbox/PC 파일을 직접 감시할 수는 없다.
- 원본에 없는 보완 사유·기관 역할·심사 판단은 만들지 않는다. 내부 확인 제안은 출처 사실과 구별한다.
- 법정/계약 기한은 미확정이며 30일은 내부 점검 구간이다.
