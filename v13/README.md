2026-10-15 검증 판본입니다. 실제 사업명, 담당자, 검토 내용이 있으므로 **비공개 저장소와 승인된 사용자에게만** 공유하세요. [웹 대시보드](대시보드_v13.html)와 [Excel 전체자료 작업본](외부사업_통합관리_전체자료_v13_검증완료.xlsx)은 같은 관리 Tool 스냅샷(2026-10-13)과 ORS 7월 31일·9월 21일 원본을 사용합니다. 웹은 압축을 푼 폴더에서 HTML을 열어야 원본 파일 링크가 작동합니다.

## 무엇이 들어 있나

- 관리 Excel 2종의 **36개 시트, 값 또는 수식이 저장된 483,492셀**을 원본 파일·시트·셀 주소와 함께 보존했습니다. 원본 수식 81,374개는 Excel `원본 수식` 시트에 텍스트로, 일반 셀과 구별되지 않는 빈 문자열 32,384개 및 기존 오류 239개는 `원본 특수셀` 시트에 주소별로 담았습니다. 오류 239개는 원본에 있던 상태이며 새 계산 결과가 아닙니다.
- ORS ZIP 2개의 **20개 XLS 파일 출현, 전체 저장 셀 286,725개**를 Excel `ORS01~20` 및 웹 `원본 전체 조회`에서 확인할 수 있습니다. ORS 원본의 빈 문자열 67,724개와 Excel 저장 과정에서 줄바꿈 표기가 달라지는 6,702개 셀의 원문(JSON)은 `원본 특수셀`에 주소별로 보존했습니다. 서로 내용이 같은 파일을 접으면 ORS 표의 업무행은 5,789행입니다. 원본 XLS 자체는 `source-archive`에 그대로 있습니다.
- 기존 분류 원장 3,419행과 회의용 통계·현재 진행·경과 구간은 그대로 유지했습니다. 이는 고유 사업 수나 신청 회차 수가 아닙니다.
- `2026 접수·검토·안내`에는 **신청일이 2026년으로 확인된 관리 원장 53행**을 담았습니다. 접수 확인, 의견 검토 상태·내용, 사무국 안내 내용·상태, 다음 조치, 업무 담당자를 별도로 입력합니다. 이 칸은 기본 `미기록`/`확인 필요`이며 원본 상태를 자동으로 완료 처리하지 않습니다.
- `2026 ORS 이력후보` 149행은 9월 산업부문 ORS의 이력에 2026년 날짜가 있는 **확인 후보**입니다. 갱신·보완·처리가 섞여 있어 신규 인입 149건으로 해석하지 않고, 관리 원장 53행과 자동으로 동일 신청이라 연결하지 않습니다.

## 월별 ORS ZIP 반영

1. 새 파일을 `incoming/YYYY-MM/`에 **받은 원본 그대로** 놓습니다. 기존 파일 이름이나 원장 셀을 바꾸지 않습니다.
2. ZIP을 `월별_ORS_미리보기.cmd` 위로 끌어다 놓습니다. `imports/*_preview.json`에서 기준일, 분류, 열 구조, 수신 범위, 보류 사유를 확인합니다. 다른 PC에서 Python 의존성이 없으면 `python -m pip install -r requirements-ingest.txt`를 한 번 실행하세요.
3. 문제가 없는 범위의 원본 보관을 확정할 때 `월별_ORS_확정반영.cmd`로 ZIP을 엽니다. DB는 최초 실행 시 `state/working.sqlite3`에 별도 생성되고, 반영 직전 `backups/`에 이전 DB가 저장됩니다. 같은 ZIP 해시는 재등록하지 않습니다. 미지원·열 구조 변경·과거 기준일 파일도 원본은 보관하지만 자동 최신 상태로 승격하지 않습니다.
4. `산출물_새판본.cmd`를 실행하면 DB 무결성을 확인하고 `snapshots/기준일_해시/`에 새 웹·Excel 판본을 만듭니다. Excel은 검증된 v13 기준 파일에 새 ORS 원본 시트를 추가하고 2026년 입력·이력 시트를 갱신합니다. Python과 `requirements-ingest.txt`의 패키지가 필요하며, 별도의 Codex/Node 생성 런타임은 필요하지 않습니다. 실패 시 웹·JSON은 유지하고 Excel 실패를 명시합니다.

이 절차는 새 ORS 원문을 **추가**합니다. 관리 Tool의 수기 진행내용, 최초 검토기관, 업무 의견·사무국 안내를 ORS 값으로 자동 덮어쓰지 않습니다. 새 ORS의 행을 기존 신청과 확정 연결하려면 번호뿐 아니라 사업명·신청유형·회차 등을 사람이 검토해야 합니다.

## 2026년 실무 입력 반영

Excel `2026 접수·검토·안내`의 노란 열을 작성하거나 웹에서 편집한 뒤 `실무 입력 CSV 내보내기`를 사용합니다. Excel/CSV 파일을 `2026_실무입력_미리보기.cmd`에 넣어 변경 목록을 확인하고, `2026_실무입력_확정반영.cmd`로 DB에 등록합니다. 기존 원본 열은 수정되지 않으며 바뀐 필드는 `workflow_history`에 이전값·새값·입력 파일 해시가 남습니다. 웹 브라우저의 임시저장만으로는 공유 DB나 Excel이 바뀌지 않습니다. DB 반영 후 `산출물_새판본.cmd`로 두 출력의 동일 판본을 만드세요.

## 판정과 한계

- 기본 `30일 초과`는 정확한 신청일에서 기준일까지의 **내부 확인 구간**입니다. 법정·계약 기한 초과가 아닙니다. 공식 기한 규정·기산일·보완 중단 및 휴일 규칙이 확인되면 별도 규칙으로 적용해야 합니다.
- 관리 Tool의 신청일이 없는 행은 2026 접수 53행에 억지로 포함하지 않았습니다. 원본 전체 조회에서 별도로 확인할 수 있습니다.
- 새 Excel의 원본 조회 시트는 **저장값**을 보여줍니다. 원본 수식은 텍스트 목록으로 보존하고 재계산하지 않습니다. 서식, 댓글, 도형, 데이터 유효성 등 원본 Excel/XLS 고유 요소는 `source-archive` 파일을 열어 확인하세요.
- 웹 정적 파일은 공동편집 서버가 아닙니다. 사용자별 임시 편집은 CSV→DB 반영 절차로 공유합니다.
- 새 관리 Excel 판본이 들어오면 기존 3,419행과 2026 53행의 연결키 이동·중복을 별도로 검토한 뒤 새 기준판을 생성해야 합니다. 월별 ORS ZIP 가져오기만으로 관리 Tool의 기준일이 바뀌지 않습니다.
